## 1. สรุปสั้นที่สุด (TL;DR)

- **คำถามวิจัย:** เราจะ “เชื่อ” โมเดลครู (teacher) ได้เมื่อไหร่ และถ้าเลือกเฉพาะคำตอบที่ครูมั่นใจ
  มาสอนโมเดลนักเรียน (student) จะได้นักเรียนที่เก่งขึ้นไหม
- **ครู:** Qwen2.5-Math-7B-Instruct (บีบอัดแบบ 4-bit) รันบนการ์ดจอ RTX 4060 Laptop (8 GB)
- **ส่วนที่ 1 (ครู):** ให้ครูตอบโจทย์คณิต 111 ข้อ ข้อละ 1 คำตอบหลัก + 8 คำตอบสุ่ม
  แล้ววัดว่า “สัญญาณความมั่นใจ” แบบไหนทำนายได้ดีว่าคำตอบถูกหรือผิด
  → **ความสอดคล้องของคำตอบ (self-consistency)** ทำนายได้ดีที่สุดใน GSM8K และ MATH
- **ส่วนที่ 2 (นักเรียน):** สอนโมเดลเล็ก Qwen2.5-0.5B ด้วยคำตอบของครู แล้วทดสอบกับโจทย์ใหม่ 640 ข้อ
  → ความแม่นยำเพิ่มจาก **25.5% เป็นประมาณ 38%** แต่การ “กรอง” คำตอบครูก่อนสอน
  ยัง**ไม่ได้ช่วยอย่างมีนัยสำคัญ** (+0.9 จุด, ช่วงความเชื่อมั่นคร่อมศูนย์)
- ผลทั้งหมดเป็น **ผลเชิงสำรวจ (exploratory)** เพราะข้อมูลน้อย ใช้เป็นแนวทาง ไม่ใช่ข้อสรุปเด็ดขาด

## 2. ที่มาและเป้าหมาย

### ปัญหา
ใน **Knowledge Distillation (KD)** เราใช้โมเดลใหญ่ (ครู) สร้างคำตอบเพื่อสอนโมเดลเล็ก (นักเรียน)
แต่ครูก็ตอบผิดได้ ถ้าเอาคำตอบผิดไปสอน นักเรียนก็จะเรียนสิ่งผิด
แนวคิดคือใช้ **“ประตูกรอง” (gate)** — สอนเฉพาะคำตอบที่ครูมั่นใจ

### คำถามที่โปรเจกต์ตอบ
1. **When (เมื่อไหร่):** สัญญาณความมั่นใจของครูบอกได้จริงไหมว่าคำตอบถูก
2. **What (อะไร):** ถ้าจะทำ gate ควรใช้สัญญาณตัวไหน
3. **ต่อยอด:** เมื่อเอา gate ไปใช้จริงตอนสอนนักเรียน ผลดีขึ้นไหม

### ขอบเขตโปรเจกต์ (สำคัญ)
แผนเดิมตั้งใจทำ 12,221 ข้อ แต่บน RTX 4060 จะใช้เวลาราว **1,000 ชั่วโมง (~6 สัปดาห์)**
จึงลดขนาดเป็น **mini study ที่เสร็จภายใน 12 ชั่วโมง** โดย**ไม่เปลี่ยนวิธีการต่อข้อ**
และได้ลบโค้ด/การตั้งค่าของแผน 12,221 ข้อออกทั้งหมดแล้ว (ยังดูได้ใน Git history)

## 3. แนวคิดสำคัญที่ต้องเข้าใจ

| คำ | ความหมายแบบเข้าใจง่าย |
| --- | --- |
| **Greedy answer** | คำตอบหลักของครู — เลือกคำที่น่าจะเป็นที่สุดทีละคำ ไม่มีการสุ่ม |
| **Samples (8 คำตอบสุ่ม)** | ให้ครูตอบซ้ำ 8 ครั้งแบบมีความสุ่ม (temperature 0.7, top-k 50) แต่ละครั้งใช้ seed ต่างกัน |
| **Entropy confidence** | วัดว่าตอนเขียนคำตอบ ครู “ลังเล” แค่ไหนในแต่ละคำ ยิ่งลังเลน้อย ค่ายิ่งใกล้ 1 |
| **Sequence probability** | ความน่าจะเป็นเฉลี่ยของทั้งคำตอบ (ค่าเฉลี่ยเรขาคณิตต่อ token) |
| **Answer-token probability** | ความน่าจะเป็นเฉพาะส่วนที่เป็นคำตอบสุดท้ายใน `\boxed{}` |
| **Self-consistency / agreement share** | สัดส่วนของ 8 คำตอบสุ่มที่ได้คำตอบตรงกับ greedy เช่น 7/8 = 0.875 |
| **Majority vote** | เลือกคำตอบที่ซ้ำมากที่สุดใน 8 คำตอบสุ่ม (มักแม่นกว่า greedy) |
| **AUROC** | วัดว่าสัญญาณแยก “ถูก” กับ “ผิด” ได้ดีแค่ไหน 1.0 = แยกได้สมบูรณ์, 0.5 = เดาสุ่ม |
| **ECE (Expected Calibration Error)** | วัดว่าความมั่นใจ “ตรงกับความจริง” ไหม เช่น มั่นใจ 80% ควรถูก ~80% ค่ายิ่งต่ำยิ่งดี |
| **Reliability diagram** | กราฟเทียบความมั่นใจกับความแม่นยำจริง ถ้าจุดอยู่บนเส้นทแยง = calibrate ดี |
| **Knowledge Distillation (KD)** | สอนโมเดลเล็กด้วยผลลัพธ์ของโมเดลใหญ่ |
| **LoRA** | วิธี fine-tune แบบประหยัด: เพิ่ม/ฝึกเฉพาะเมทริกซ์เล็ก ๆ แทนการฝึกทั้งโมเดล |
| **NF4 / 4-bit** | บีบอัดน้ำหนักโมเดลให้เหลือ 4 บิต เพื่อให้โมเดล 7B ใส่ใน GPU 8 GB ได้ |
| **Paired bootstrap / 95% CI** | สุ่มชุดข้อสอบซ้ำหลายพันครั้งเพื่อดูว่าความต่างของสองเงื่อนไข “ของจริง” หรือแค่บังเอิญ ถ้าช่วงคร่อม 0 = ยังสรุปไม่ได้ |
| **Exploratory** | ผลเพื่อสำรวจแนวโน้ม ไม่ใช่หลักฐานเพียงพอสำหรับตัดสินใจขั้นสุดท้าย |

## 4. ส่วนที่ 1: การทดลองครู (Teacher reliability)

### การตั้งค่า
| รายการ | ค่า |
| --- | --- |
| โมเดล | `Qwen/Qwen2.5-Math-7B-Instruct` revision `ef9926d7…` |
| ความแม่นยำตัวเลข | NF4 double quantization, คำนวณแบบ FP16 |
| ฮาร์ดแวร์ | NVIDIA RTX 4060 Laptop GPU 8 GB |
| Profile / seed | `mini_12h` / 42 |
| ข้อมูล | GSM8K 40 ข้อ, MATH 21 ข้อ (7 วิชา × 3), GSM-Plus 50 ข้อ (1 ข้อต่อโจทย์ต้นฉบับ) |
| ต่อข้อ | 1 greedy + 8 samples, ยาวสูงสุด 1,024 token |

**ชุดข้อมูล:** GSM8K = โจทย์ปัญหาคณิตระดับประถม, MATH = คณิตแข่งขัน 7 วิชา,
GSM-Plus = GSM8K ที่ถูกดัดแปลง (เช่น ใส่ข้อมูลหลอก เปลี่ยนตัวเลข) เพื่อทดสอบความทนทาน

### การรัน
- เริ่ม 23:02 จบรอบแรก 04:40 (~5.6 ชั่วโมง) ได้ 109/111 ข้อ
- 2 ข้อล้มเพราะ **RAM ของเครื่องไม่พอ** (ระบบเช็กก่อนแล้วข้ามอย่างปลอดภัย) → รันซ้ำเฉพาะ 2 ข้อนั้น → **111/111 ครบ**
- ความเร็วประมาณ **19.4 ข้อ/ชั่วโมง**
- GPU ร้อน ~85 °C และถูกลดความเร็วเล็กน้อยจากความร้อน

### ผลลัพธ์
| ชุดข้อมูล | Greedy ถูก | Majority vote ถูก | Agreement เฉลี่ย (ข้อที่ถูก / ผิด) | สัญญาณที่ดีที่สุด (AUROC) |
| --- | ---: | ---: | ---: | --- |
| GSM8K | 85.0% | 90.0% | 0.97 / 0.54 | Self-consistency (0.895) |
| MATH | 71.4% | 81.0% | 0.85 / 0.17 | Self-consistency (0.950) |
| GSM-Plus | 81.2% | 83.3% | 0.97 / 0.60 | Sequence probability (0.858) |

AUROC ของทุกสัญญาณ:

| สัญญาณ | GSM8K | GSM-Plus | MATH |
| --- | ---: | ---: | ---: |
| Entropy confidence | 0.765 | 0.846 | 0.900 |
| Answer-token probability | 0.716 | 0.760 | 0.867 |
| Sequence probability | 0.789 | **0.858** | 0.867 |
| Self-consistency agreement | **0.895** | 0.736 | **0.950** |

ECE ของ self-consistency ต่ำที่สุดทุกชุด (~0.10–0.13) แปลว่าความมั่นใจแบบนี้ “ตรงกับความจริง” ที่สุด
ส่วน entropy มี ECE สูงกว่า (0.14–0.24) — คือครู**มั่นใจเกินจริง**

### บทเรียนจากส่วนนี้
1. **เมื่อครูผิด คำตอบสุ่มของครูมักไม่ตรงกัน** → agreement ต่ำ = สัญญาณเตือนที่ดี
2. **Majority vote แม่นกว่า greedy** 2–10 จุด
3. **มีข้อผิดที่ gate จับไม่ได้:** เช่นโจทย์ GSM8K ข้อ 403 ครูตอบ 135 (ที่ถูกคือ 81)
   และคำตอบสุ่มทั้ง 8 ก็ตอบ 135 เหมือนกัน → ครู “ผิดอย่างมั่นใจ”
4. ตัวอย่างข้อที่ gate ช่วยได้: MATH intermediate algebra ข้อ 607 greedy ผิด
   แต่ 6/8 คำตอบสุ่มตอบ 32 ซึ่งถูก → majority vote แก้ได้

ดูทุกข้อได้ที่ [`results/mini12h-rtx4060-20261001/SAMPLE.md`](../results/mini12h-rtx4060-20261001/SAMPLE.md)

## 5. ส่วนที่ 2: Mini distillation (สอนนักเรียน)

### การตั้งค่า
| รายการ | ค่า |
| --- | --- |
| นักเรียน | `Qwen/Qwen2.5-0.5B` (base) |
| วิธีฝึก | LoRA rank 16 ทุก linear layer, 2 epochs, learning rate 2e-4, batch 16, seed 0 |
| ข้อมูลฝึก | คำตอบของครูจาก 111 ข้อ (ข้อละ greedy + 8 samples ตัดที่ยาวเกิน/ไม่มีคำตอบออก) |
| ข้อสอบ | **640 ข้อใหม่** ที่ไม่ซ้ำกับข้อฝึก: GSM8K 300, MATH 140, GSM-Plus 200 |
| การให้คะแนน | ตอบแบบ greedy ยาวสูงสุด 512 token ตรวจด้วย Math-Verify ที่คำตอบ `\boxed{}` แรก |

ตัดโจทย์ GSM-Plus ที่ดัดแปลงจากโจทย์ฝึกออกด้วย เพื่อกันการ “จำข้อสอบ”

### 4 เงื่อนไขที่เปรียบเทียบ
| เงื่อนไข | สอนด้วยอะไร | จำนวนคำตอบ |
| --- | --- | ---: |
| `base` | ไม่สอนเลย (จุดเริ่มต้น) | 0 |
| `kd_all` | คำตอบครูทั้งหมด | 955 |
| `kd_gated` | เฉพาะคำตอบที่ตรงกับ majority และ majority ≥ 75% (**ไม่ใช้เฉลย**) | 824 |
| `kd_oracle` | เฉพาะคำตอบที่ถูกตามเฉลย (ใช้อ้างอิง ใช้จริงไม่ได้เพราะต้องมีเฉลย) | 797 |

### ผลลัพธ์
| เงื่อนไข | GSM8K | GSM-Plus | MATH | รวม |
| --- | ---: | ---: | ---: | ---: |
| base | 28.3% | 22.5% | 23.6% | 25.5% |
| kd_all | 46.7% | 33.0% | 25.7% | 37.8% |
| kd_gated | 46.7% | **36.0%** | 25.7% | **38.8%** |
| kd_oracle | 44.3% | 33.0% | 27.1% | 37.0% |

| เปรียบเทียบ | ต่าง | 95% CI | แปลผล |
| --- | ---: | --- | --- |
| kd_all − base | +12.3 | [+8.3, +16.3] | **ช่วยจริง** |
| kd_gated − base | +13.3 | [+9.4, +17.2] | **ช่วยจริง** |
| kd_gated − kd_all | +0.9 | [−2.0, +4.1] | ยังสรุปไม่ได้ |
| kd_oracle − kd_all | −0.8 | [−3.9, +2.3] | ยังสรุปไม่ได้ |

### บทเรียนจากส่วนนี้
1. **Distillation ได้ผลชัดเจน** แม้มีข้อมูลฝึกแค่ 111 ข้อ (+12–13 จุด) ส่วนใหญ่ดีขึ้นใน GSM8K/GSM-Plus
   แต่ MATH แทบไม่ขยับ (โจทย์ยากเกินโมเดล 0.5B)
2. **Gate ยังไม่ได้พิสูจน์ว่าช่วย** เพราะครูถูกเป็นส่วนใหญ่อยู่แล้ว gate จึงตัดข้อมูลออกแค่ 14–17%
   ข้อมูลเสียที่ต้องกำจัดมีน้อย ผลต่างจึงเล็กเกินกว่าจะวัดได้ด้วยข้อสอบ 640 ข้อ
3. แม้แต่ `kd_oracle` (ใช้เฉลย) ก็ไม่ชนะ → ในสภาพนี้ “ปริมาณข้อมูล” สำคัญพอ ๆ กับ “ความถูกต้อง”

## 6. ข้อจำกัดที่ต้องรู้ (อย่าตีความเกินนี้)

- ครูทดสอบแค่ 111 ข้อ (21–50 ข้อต่อชุด) → ตัวเลข AUROC/ECE เป็นแนวโน้มเท่านั้น
- นักเรียนฝึก**แค่ seed เดียว** ขนาดโมเดลเดียว และข้อมูลฝึกแต่ละเงื่อนไขมีขนาดไม่เท่ากัน
- คำตอบของนักเรียน 11–20% ถูกตัดที่ 512 token ก่อนจะตอบเสร็จ
- ไม่มีการทดสอบหาค่า batch ที่ดีที่สุด และไม่มี external review — ใช้ค่าระวังภัยพร้อมระบบลด batch อัตโนมัติเมื่อหน่วยความจำไม่พอ
- ข้อความที่สุ่มได้อาจต่างไปเมื่อรันบนฮาร์ดแวร์/ซอฟต์แวร์ต่างกัน แม้ seed เดียวกัน
- รายงานจึง**ไม่แนะนำ gate สำหรับใช้งานจริง** (สถานะ `exploratory`)

## 10. ถ้าจะต่อยอด ควรทำอะไรต่อ

1. **พิสูจน์ผลของ gate ให้ชัด:** ฝึกนักเรียนเงื่อนไขละ 3–5 seeds หรือเพิ่มข้อมูลครูให้มากขึ้น
   (ต้องใช้ข้อมูลที่ครูผิดบ่อยขึ้น gate ถึงจะมีผล)
2. **ลดการตัดคำตอบ:** เพิ่มความยาวคำตอบนักเรียนเป็น 1,024 token หรือใช้ Qwen2.5-0.5B-Instruct
3. **ลองเกณฑ์ gate อื่น:** เช่น 0.5 หรือ 0.875 และเลือกเกณฑ์จากชุด validation แยก ไม่ใช่ชุดทดสอบ
4. **ลอง gate แบบผสม:** self-consistency สำหรับ GSM8K/MATH และ sequence probability สำหรับ GSM-Plus

## 11. คำถามที่อาจถูกถาม และคำตอบสั้น ๆ

- **ทำไมไม่ทำ 12,221 ข้อตามแผน?** ใช้เวลา ~1,000 ชั่วโมงบน RTX 4060 จึงลดเป็น 111 ข้อที่เสร็จใน 12 ชั่วโมง โดยวิธีการต่อข้อเหมือนเดิม
- **สัญญาณไหนดีที่สุด?** Self-consistency ใน GSM8K และ MATH, sequence probability ใน GSM-Plus แต่ข้อมูลน้อย
- **Distillation ได้ผลไหม?** ได้ชัดเจน +12–13 จุด
- **Gate ช่วยไหม?** ตัวเลขดีขึ้นเล็กน้อย (+0.9) แต่ยังแยกไม่ออกจากความบังเอิญ
- **ทำไม entropy ไม่ดีเท่า?** ครูมั่นใจระดับ token สูงแม้ตอนตอบผิด (overconfident) ส่วนการตอบซ้ำหลายครั้งเผยความไม่แน่นอนได้ดีกว่า
- **ผลนี้ใช้ตัดสินใจจริงได้ไหม?** ยังไม่ควร เป็นผลสำรวจที่ชี้ทิศทางการทดลองครั้งต่อไป
